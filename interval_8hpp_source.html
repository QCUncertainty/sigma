379 Interval& operator*=(const Interval& rhs) {
380 /* Putting this here in case it's helpful for optimizing.
381 * Given two intervals X = [a, b] and Y = [c, d], the product X * Y is:
382 * [min(ac, ad, bc, bd), max(ac, ad, bc, bd)]. Thus the entire product
383 * is determined by four sub-products: ac, ad, bc, and bd. Simple
384 * combinatorics suggests that there are 16 possible products for X*Y,
385 * (i.e., chose one sub-product for the new lower bound and one for the
386 * new upper bound).
387 *
388 * If we know that a < b and c < d, i.e., our intervals are not points,
389 * we can immediately rule out eight products:
390 *
391 * - [ac, ac], [ad, ad], [bc, bc], and [bd,bd].
392 * - [ac, ad], [ac, bc], [bd, bc], and [bd,ad].
393 *
394 * Proofs that these products are impossible are given below.
395 *
396 * To prove the first four products are impossible consider [ac, ac],
397 * which implies:
398 *
399 * - ac <= ad <= ac,
400 * - ac <= bc <= ac, and
401 * -ac <= bd <= ac
402 *
403 * The first inequality means c == d, the second means a == b. Which
404 * means X = [a, a] and Y = [c, c], i.e. X and Y must be points. This
405 * contridicts our assumption that X and Y are not points and thus these
406 * four products will never appear. Similar logic holds for the other
407 * three products of the form [xy, xy].
408 *
409 * Now consider the product [ac, ad]. This implies:
410 *
411 * - ac <= bc <= ad, and
412 * - ac <= bd <= ad
413 *
414 * If a is negative, then d <= bc/a <= c, which is not possible with the
415 * assumption c < d. If a is zero, the product [ac, ad] is [0, 0], which
416 * means bc and bd must be zero. b can't be zero because then
417 * X = [0, 0]. This would then mean that both c and d must be zero, but
418 * c and d both can't be zero because then Y = [0, 0]. Thus a must be
419 * positive. If a is positive, then so is b. If c >= 0 then d is
420 * positive and then we have that bd > ad, which is not consistent with
421 * bd <= ad. c also can't be negative because then bc < ac. We thus
422 * conclude that [ac, ad] is not possible.
423 *
424 * The remaining three proofs follow similarly. Let "target interval"
425 * refer to the interval we are proving is not possible. Then the proof
426 * proceeds by showing:
427 *
428 * - We get two inequalities by forcing the remaining two sub-products
429 * to be bounded by the target interval. Above this showed that bc and
430 * bd must be in the interval [ac, ad]. We term these the "implicit
431 * sub-products" because they do not show up explicitly in the target
432 * interval.
433 * - One of X or Y's bounds will appear twice in the target interval. We
434 * term this the "common bound". Above this bound was "a".
435 * - If the common bound is the lower bound of X(Y) try assuming the
436 * commonbound is negative and dividing the inequalities by it. If the
437 * common bound is the upper bound, instead divide the inequalities by
438 * the positive of it. This will cause one of the two inequalities to
439 * be a contradiction eliminating that possibility. Above this ruled
440 * out "a" being negative.
441 * - The common bound can't be zero otherwise X and Y collapse to
442 * point intervals.
443 * - This means the common bound must be positive (negative) for a lower
444 * (upper) bound. In turn, the "other bound" must be positive
445 * (negative) too. Above this "other bound" was "b".
446 * - The implicit sub-products will share other bound. If other bound is
447 * the upper (lower) bound, then assume that the lower (upper) bound
448 * of the other interval is positive (negative) or zero. This
449 * will force the upper (lower) bound of the other interval to be
450 * positive (negative) too. All bounds will now have the same sign
451 * and violate one of the inequalities.
452 * - The last possibility is then that the lower (upper) bound of the
453 * other interval has the opposite sign as the common bound. This too
454 * will violate one of the inequalities and we conclude that the
455 * target interval is not possible.
456 */
457

459 return *this = Interval();
460 } else if(width() == 0 && rhs.width() == 0) { // Both points

616bool operator==(const Interval<T1>& lhs, const Interval<T2>& rhs) {
617 if constexpr(!std::is_same_v<T1, T2>) return false;

622 return lhs.lower() == rhs.lower() && lhs.upper() == rhs.upper();
