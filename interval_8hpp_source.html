341template<typename ValueType>
342Interval<ValueType>& Interval<ValueType>::operator*=(const Interval& rhs) {
343 /* Putting this here in case it's helpful for optimizing.
344 * Given two intervals X = [a, b] and Y = [c, d], the product X * Y is:
345 * [min(ac, ad, bc, bd), max(ac, ad, bc, bd)]. Thus the entire product
346 * is determined by four sub-products: ac, ad, bc, and bd. Simple
347 * combinatorics suggests that there are 16 possible products for X*Y,
348 * (i.e., chose one sub-product for the new lower bound and one for the
349 * new upper bound).
350 *
351 * If we know that a < b and c < d, i.e., our intervals are not points,
352 * we can immediately rule out eight products:
353 *
354 * - [ac, ac], [ad, ad], [bc, bc], and [bd,bd].
355 * - [ac, ad], [ac, bc], [bd, bc], and [bd,ad].
356 *
357 * Proofs that these products are impossible are given below.
358 *
359 * To prove the first four products are impossible consider [ac, ac],
360 * which implies:
361 *
362 * - ac <= ad <= ac,
363 * - ac <= bc <= ac, and
364 * -ac <= bd <= ac
365 *
366 * The first inequality means c == d, the second means a == b. Which
367 * means X = [a, a] and Y = [c, c], i.e. X and Y must be points. This
368 * contridicts our assumption that X and Y are not points and thus these
369 * four products will never appear. Similar logic holds for the other
370 * three products of the form [xy, xy].
371 *
372 * Now consider the product [ac, ad]. This implies:
373 *
374 * - ac <= bc <= ad, and
375 * - ac <= bd <= ad
376 *
377 * If a is negative, then d <= bc/a <= c, which is not possible with the
378 * assumption c < d. If a is zero, the product [ac, ad] is [0, 0], which
379 * means bc and bd must be zero. b can't be zero because then
380 * X = [0, 0]. This would then mean that both c and d must be zero, but
381 * c and d both can't be zero because then Y = [0, 0]. Thus a must be
382 * positive. If a is positive, then so is b. If c >= 0 then d is
383 * positive and then we have that bd > ad, which is not consistent with
384 * bd <= ad. c also can't be negative because then bc < ac. We thus
385 * conclude that [ac, ad] is not possible.
386 *
387 * The remaining three proofs follow similarly. Let "target interval"
388 * refer to the interval we are proving is not possible. Then the proof
389 * proceeds by showing:
390 *
391 * - We get two inequalities by forcing the remaining two sub-products
392 * to be bounded by the target interval. Above this showed that bc and
393 * bd must be in the interval [ac, ad]. We term these the "implicit
394 * sub-products" because they do not show up explicitly in the target
395 * interval.
396 * - One of X or Y's bounds will appear twice in the target interval. We
397 * term this the "common bound". Above this bound was "a".
398 * - If the common bound is the lower bound of X(Y) try assuming the
399 * commonbound is negative and dividing the inequalities by it. If the
400 * common bound is the upper bound, instead divide the inequalities by
401 * the positive of it. This will cause one of the two inequalities to
402 * be a contradiction eliminating that possibility. Above this ruled
403 * out "a" being negative.
404 * - The common bound can't be zero otherwise X and Y collapse to
405 * point intervals.
406 * - This means the common bound must be positive (negative) for a lower
407 * (upper) bound. In turn, the "other bound" must be positive
408 * (negative) too. Above this "other bound" was "b".
409 * - The implicit sub-products will share other bound. If other bound is
410 * the upper (lower) bound, then assume that the lower (upper) bound
411 * of the other interval is positive (negative) or zero. This
412 * will force the upper (lower) bound of the other interval to be
413 * positive (negative) too. All bounds will now have the same sign
414 * and violate one of the inequalities.
415 * - The last possibility is then that the lower (upper) bound of the
416 * other interval has the opposite sign as the common bound. This too
417 * will violate one of the inequalities and we conclude that the
418 * target interval is not possible.
419 */
420
421 if(empty() || rhs.empty()) { return *this = Interval(); }
422
423 // Boost rounds each of the four sub-products outward before taking the
424 // extremes.
425 m_interval_ = *m_interval_ * *rhs.m_interval_;
426 return *this;
427}
