Detailed Description

template<typename IntervalType>
class sigma::Triplex< IntervalType >

Models an interval together with a best estimate inside it.

A triplex number \( \langle a, m, b \rangle \) is an interval \( [a, b] \) plus a distinguished member \( m \) of it, the nominal value. The interval is a rigorous enclosure, computed exactly as IntervalType would compute it. The nominal value is computed in ordinary, round-to-nearest floating point from the operand nominal values, so the nominal value of any triplex computation is the result of the same computation performed with plain value_t on the input nominal values. Nothing ties the nominal value to the median of the interval; in general they differ.

If the scalar computation overflows, or otherwise produces a non-finite value, the nominal value is kept anyway. Such a nominal value is not a member of the interval, and can be detected with std::isfinite(nominal()).

See the Triplex Arithmetic page of the documentation for the full design.

Template Parameters
IntervalTypeThe type of the bounds: Interval<T> for closed bounds or GeneralInterval<T> for bounds that may be open.

◆ operator<()

template<typename IntervalType>
bool operator< ( const Triplex< IntervalType > & lhs,
const Triplex< IntervalType > & rhs )
related

Orders two triplex numbers, primarily by their nominal values.

As for Interval's ordering by median, this is a total order meant for sorting and not an enclosure relation. Triplex numbers are compared lexicographically by nominal value, then lower bound, then upper bound, and then, for a general triplex, by the openness of the lower and upper bounds, with a closed bound before an open one. The tie-breaks make the order consistent with operator==: neither of two triplex numbers precedes the other exactly when they are equal, so they can be keys of ordered containers. The empty triplex sorts before every non-empty one.

As for plain floating point, a NaN nominal value has no place in the order.
